# Workflow Skill Router v2.1.0

> Official release.

## Why V2

Workflow Skill Router chooses one lead Skill for each phase of the work, adds
only the support that phase needs, and shows the route before the agent
continues. It is a pre-execution Skill-selection layer: it does not replace
Host permissions, approvals, sandboxing, or production orchestration. This
release brings it to Claude Code and makes the workflow memory layer available
as an opt-in feature.

## What is new

- **Claude Code Plugin.** The repository now hosts a Claude Code marketplace in
  `.claude-plugin/marketplace.json`. The Plugin in
  `plugins/claude-code/workflow-skill-router/` runs the same MCP server and
  local Python runtime as the Codex Plugin, with a Claude Code version of the
  Router SKILL.
- **Host-aware workspace Profiles.** `WORKFLOW_SKILL_ROUTER_HOST` selects
  `codex` (default) or `claude-code`. The Claude Code host reads workspace
  Profiles and Memory policies from `.claude/` before `.codex/`. Personal
  Profiles and local state are shared by both hosts. An unknown host value
  stops the MCP server and the Python bridge before any workspace file is read.
- **Adaptive Workflow Memory, off by default.** Eight typed MCP tools record
  eligible completed routes, propose reviewable Profile updates, version and
  roll back managed Profiles, and purge explicit Memory scopes. Nothing is
  captured until a policy turns Memory on. There is no background learning and
  no telemetry. The MCP surface grows from 12 to 20 tools.
- **Bilingual deterministic classification.** The structural classifier
  revision `deterministic-objective-v2` recognizes common Traditional Chinese
  repair, requirements, cross-project, and progress-retention signals, and
  ignores negated long-running signals. Existing records keep their original
  classifier revision on replay.
- **Actionable local work loop.** `get_next_work`, `record_work_event`, and
  `evaluate_gate` report the Router-owned local contract more precisely.

## Choose your install mode

- **Claude Code:**
  `/plugin marketplace add eric861129/Workflow-skill-router`, then
  `/plugin install workflow-skill-router@workflow-skill-router`. Requires
  Node.js 24+ and Python 3.11+.
- **Codex Plugin + MCP:**
  `workflow-skill-router-plugin-v2.1.0.zip` contains the bundled local control
  plane and typed runtime readiness. The Codex marketplace can also be pinned
  with `--ref v2.1.0`.
- **Skill-only:**
  `workflow-skill-router-skill-v2.1.0.zip` preserves routing and disclosure
  instructions without durable state or verified Host authority.

## Canonical Plugin distribution

`eric861129/Workflow-skill-router` remains the canonical development and
governance surface for both hosts. The standalone
`eric861129/workflow-skill-router-plugin` repository is the generated target
for root-level Codex Plugin installation; the trusted release workflow
synchronizes it only after the frozen-source preflight succeeds, and its HOL
Plugin Scanner must pass before the target tag is created. The Claude Code
Plugin installs from the canonical repository's marketplace.

## Compatibility and evidence

Codex keeps its existing data directory, `.codex/` workspace paths, and default
host behavior. MCP tool descriptions now name the host generically. Persisted
schemas are unchanged; Workflow Memory creates its optional store only after a
policy enables it.

This release changes routing instructions and classification, so it does not
inherit earlier behavior evidence. Its Behavior gate is the frozen six-case
paired beta smoke run against the frozen source revision: 36 attempts across
42 model turns. The maintainer attestation records that run, its model
configuration, and its review. Claude Code support has not been evaluated with
Claude models. The release does not claim verified Skill activation, token
reduction, or task-outcome improvement.
