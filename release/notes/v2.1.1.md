# Workflow Skill Router v2.1.1

> Official release.

## Why V2

Workflow Skill Router chooses one lead Skill for each phase of the work, adds
only the support that phase needs, and shows the route before the agent
continues. It is a pre-execution Skill-selection layer for Claude Code and
Codex: it does not replace Host permissions, approvals, sandboxing, or
production orchestration.

## Why this patch

`v2.1.1` is a dependency security patch for `v2.1.0`. The bundled MCP server
in `v2.1.0` ships `zod` 4.1.12, which is affected by
[GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)
(High): validating oversized constrained collections can exhaust memory. The
MCP server validates tool input from the local Host over stdio; it does not
open a network listener. Upgrade if you run the Plugin from `v2.1.0`.

## What changed

- **Bundled runtime.** `zod` 4.6.7 and `@modelcontextprotocol/sdk` 1.32.2 are
  rebuilt into `mcp/server.bundle.mjs` for both the Codex and Claude Code
  Plugins.
- **Lockfile advisories.** `body-parser` 2.4.0 and `fast-uri` 3.1.9 close the
  remaining Plugin lockfile advisories. Neither package is in the shipped
  bundle. `npm audit` reports zero findings for the Plugin and the site.
- **Tool schemas.** With `zod` 4.6, nullable strings are emitted as
  `"type": ["string", "null"]` instead of an equivalent `anyOf`, and Memory
  `date-time` output fields require seconds. The runtime already writes
  millisecond UTC timestamps, so valid output is unchanged.
- **Release supply chain.** The trusted distribution job verifies the
  generated target governance with the verifier from the dispatch revision,
  and the generated target's HOL Plugin Scanner workflow pins
  `actions/checkout` v7.0.1 and `ai-plugin-scanner-action` v1.2.811.

Routing instructions, classification, MCP tool names and semantics, and
persisted schemas are unchanged.

## Choose your install mode

- **Claude Code:**
  `/plugin marketplace add eric861129/Workflow-skill-router`, then
  `/plugin install workflow-skill-router@workflow-skill-router`. Requires
  Node.js 24+ and Python 3.11+.
- **Codex Plugin + MCP:**
  `workflow-skill-router-plugin-v2.1.1.zip` contains the bundled local control
  plane and typed runtime readiness. The Codex marketplace can also be pinned
  with `--ref v2.1.1`.
- **Skill-only:**
  `workflow-skill-router-skill-v2.1.1.zip` preserves routing and disclosure
  instructions without durable state or verified Host authority. Its routing
  instructions are unchanged from `v2.1.0`.

## Canonical Plugin distribution

`eric861129/Workflow-skill-router` remains the canonical development and
governance surface for both hosts. The standalone
`eric861129/workflow-skill-router-plugin` repository is the generated target
for root-level Codex Plugin installation; the trusted release workflow
synchronizes it only after the frozen-source preflight succeeds, and its HOL
Plugin Scanner must pass before the target tag is created. Dependency updates
for the generated target are made here, not in the generated target.

## Compatibility and evidence

This patch does not change routing behavior, so it inherits the reviewed
`v2.1.0` Behavior evidence rather than claiming a new model run: the frozen
six-case paired beta smoke, 36 attempts across 42 model turns, run through the
Claude Code driver. The maintainer attestation records that inheritance and
the deterministic gates for this revision. Codex models were not re-qualified.
The release does not claim verified Skill activation, token reduction, or
task-outcome improvement.

## Verify this release

- Validate `checksums.sha256` before installation.
- Inspect the `maintainer-attestation` for the frozen source revision before
  relying on behavior evidence.
- Inspect the `SBOM` at `sbom/workflow-skill-router-v2.1.1.spdx.json` and
  `provenance/workflow-skill-router-v2.1.1.json`.
- Verify the generated target governance with
  `python scripts/verify-plugin-distribution-governance.py`.
