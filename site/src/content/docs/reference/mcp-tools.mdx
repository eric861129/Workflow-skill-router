## Runtime profile

Current generated profile: **{toolData.runtime_profile}**

This generated profile describes the **prepared GA candidate**, which is **not included in published beta.3**. Within the original twelve tools, it retains **4 always local-ready + 3 Router-owned conditional-local** tools. Conditional-local does not mean `7/12 local-ready`: it is available only for a validated Router-owned work graph with no Native Goal authority. Explicit Skill Lock and consent remain unchanged. A local gate is advisory and is not Skill activation, deployment, production approval, or Host evidence.

The current source adds eight opt-in Memory tools, for **20** tools total: **10 local-ready**, **5 conditional-local**, 2 verified-Host-required, and 3 configured-adapter-required. The two additional conditional tools are Profile transition and rollback; their prerequisites are the effective Memory policy, an exact reviewed Proposal, and a locally permitted target, not a Router-owned work graph. Memory remains default-off. Status, candidate list, and Profile preview are read-only; R1 purge requires explicit confirmation and reports unsupported scopes without claiming deletion. These source capabilities do not change the published beta.3 package.

Native Goal boundaries remain tool-specific: `verified-host-scheduler` for next work, `verified-event-store` plus `activation-receipt-verifier` for formal progress, and `verified-evidence-store` plus `gate-authority` for gates. Missing graphs require local creation or replay through `router-owned-work-graph`; corrupt graphs return a sanitized `internal-error`. Every unavailable or unsafe branch must **fail closed**.

## Adaptive Workflow Memory public contract

The public surface contains **20** MCP tools. Memory uses a separate **Operational DB** and **Optional Memory DB**. Managed writes are limited to `managed-personal` and `managed-workspace-local`; User-owned Profile writes still require their original authority.

The four decisions remain separate: policy autonomy, trusted Workspace binding, Profile ownership/target authority, and Runtime/Side-effect execution authority. A trusted root is not a Host write grant.

**Skill consistency** is **unavailable** without **receipt evidence**. A planned route may be `intended-unverified`; it is not activation proof. The Memory Flight Recorder uses `fixture-trace` or sanitized runtime records. Its `deterministic-local-pilot` is **not Model Evidence** and never contains actual Personal Memory.

### Memory tool subset

The eight Memory tools are `get_memory_status`, `remember_workflow`, `record_route_feedback`, `list_workflow_candidates`, `preview_profile_update`, `transition_profile_update`, `rollback_profile_revision`, and `purge_workflow_memory`. Status/list/preview are read-only; transition/rollback remain conditional-local; purge is explicit and destructive.
